### Deviation from the brief

The brief puts the picker metadata (tag, name, biome pool) in `src/enemies/mid/<kind>.ts`. That can't work with those modules staying pure: `midpick`, `runsave` and `warmplan` read it at load, and a kind's file imports the sim and, through `core.ts`, the DOM. One ES module can't be both. So the metadata is one row in `roster.ts`. **Adding a held biome kind is still one new file per side plus one line.** Both folders load by glob, so the row is the only shared line, and the render side needs none.

## Stubs and open risks

1. **Orbit and ship kinds have no spawn path yet.** A row in those pools passes every check and never appears, even under the flag. LS2-orbit and LS2-ship must wire it; the recipe says where. Those lanes also need `boot: true`.
2. **The WIP pool is every biome pool, as in phase 1.** A `wip` ice kind can appear in a fire stage, so it needs a sound crossover. Narrowing a stage to its own pool is a picker rule left for when the pools fill.
3. **Lists left by choice:** `MID_HP` (tuning; an unlisted kind takes `et.hp`), `DEPTH.w` (pinned by test), `music.ts` `ufoMix`, and the `k === 'ufo'` branches in the probes, which a new DRIFT kind needs to extend.
4. **Roster order is load-bearing.** A row inserted mid-list moves every run's picks. The recipe and the header say to append; no test enforces it beyond the first five rows.
5. **Nit, left:** `hud.ts` spreads `MID_NAMES` per frame for a mini with no title. The old code built an object there too, and changing it would have voided the gates.
6. **The commit hook warns** of hardcoded gameplay values in `cyst.ts` and `update.ts`. These are existing values, moved, not new.
